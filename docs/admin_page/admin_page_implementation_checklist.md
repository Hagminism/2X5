# 관리자 페이지 구현 체크리스트 (DoD)

## 1. 권한/상태 모델 확정

### 선행조건
- 관리자 기능 범위가 PRD 기준으로 합의되어 있어야 한다.

### 완료조건
- [ ] `role`, `partner_status` enum 값이 확정되어 있어야 한다.
- [ ] 승인 전/후 기능 허용 매트릭스가 문서화되어 있어야 한다.
- [ ] 라우트/화면 접근 정책표가 확정되어 있어야 한다.

---

## 2. DB 스키마 구축

### 선행조건
- 권한/상태 모델이 확정되어 있어야 한다.

### 완료조건
- [ ] `owner_verifications`, `resources`, `reservations` 테이블이 생성되어 있어야 한다.
- [ ] `coupon_policies`, `user_coupon_wallets`, `coupon_ledger` 테이블이 생성되어 있어야 한다.
- [ ] `business_number` unique, 좌표 무결성, `idempotency_key` 제약이 반영되어 있어야 한다.
- [ ] 마이그레이션 up/down 검증이 완료되어 있어야 한다.

---

## 3. 접근 제어 구현

### 선행조건
- 스키마와 접근 정책표가 확정되어 있어야 한다.

### 완료조건
- [ ] `owner_id` 기준 조회/수정 스코프가 강제되어 있어야 한다.
- [ ] `partner_status != approved` 상태에서 제한 기능이 차단되어 있어야 한다.
- [ ] 교차 테넌트 접근 차단 테스트가 통과되어 있어야 한다.

---

## 4. 회원가입/온보딩 개편

### 선행조건
- 접근 제어의 기본 동작이 확보되어 있어야 한다.

### 완료조건
- [ ] 관리자 가입 폼이 기본 정보만 수집하도록 변경되어 있어야 한다.
- [ ] 가입 직후 관리자 온보딩/인증 유도 라우팅이 동작해야 한다.
- [ ] 기존 파트너 가입의 사업자 입력 경로가 제거 또는 비활성화되어 있어야 한다.

---

## 5. 사업자 인증 기능

### 선행조건
- `owner_verifications`에 데이터 저장이 가능해야 한다.

### 완료조건
- [ ] 사업자 정보 입력/첨부/제출/재제출 흐름이 동작해야 한다.
- [ ] 상태(`pending`, `approved`, `rejected`) 및 반려 사유 조회가 가능해야 한다.
- [ ] 국세청 검증 결과 저장 흐름(성공/실패)이 동작해야 한다.

---

## 6. 업장 관리 기능

### 선행조건
- 사업자 인증 제출 흐름이 동작해야 한다.

### 완료조건
- [ ] 업장 기본 정보/위치/운영시간 CRUD가 동작해야 한다.

- [ ] 승인 전 편집 가능 범위가 정책과 일치해야 한다.

## 9. 쿠폰/스탬프 자동 정산

### 선행조건
- 예약 완료(또는 이용 완료) 이벤트가 신뢰 가능해야 한다.

### 완료조건
- [ ] 쿠폰/스탬프 정책 CRUD가 동작해야 한다.

- [ ] 동일 이벤트 재처리 시 중복 정산이 발생하지 않아야 한다.

### 완료조건

## 11. 실시간 반영/운영 추적

### 선행조건
- 주요 도메인 기능이 통합 동작해야 한다.

### 완료조건
- [ ] 예약/정산 이벤트가 관리자 화면에 지연 허용치 내 반영되어야 한다.
- [ ] 인증/예약/정산 감사 로그를 추적할 수 있어야 한다.
- [ ] 장애 분석용 최소 로그 포인트가 확보되어야 한다.

## 12. 통합 검증(E2E)

### 선행조건
- 전 단계 기능이 통합 완료되어 있어야 한다.

### 완료조건
- [ ] 핵심 시나리오(가입 -> 인증 제출 -> 승인 -> 업장 등록 -> 예약 운영 -> 정산)가 통과되어야 한다.
- [ ] 권한/정합성/정산 회귀 테스트가 통과되어야 한다.
- [ ] 운영 체크리스트 기준을 충족해야 한다.
